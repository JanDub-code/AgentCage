AgentCage

ac — One project, one agent, a disposable rootless Podman container.

The current directory is mounted read/write. Your host home is not separately mounted. Network access is enabled, and normal agent runs reuse selected saved login files. Project changes, the image, and saved logins survive container removal.

For a run without saved credentials, use ac codex --no-login. Files already in your project remain accessible. Read the security boundaries.

Installation

These source installation methods need Git and Rust/Cargo. The curl method also needs curl. They build the repository's current main branch. For a binary package, see the package installation instructions.

To run agents you need Linux x86_64, rootless Podman with crun and cgroups v2. Check the version requirements and validation matrix. Docker is not supported.

$install_script=$(curl -fsSL https://raw.githubusercontent.com/JanDub-code/AgentCage/main/install.sh) && { [ -n "$install_script" ] || { printf '%s\n' 'Installer download was empty.' >&2; false; }; } && printf '%s\n' "$install_script" | sh
$cargo install --git https://github.com/JanDub-code/AgentCage.git --locked

Cargo installs to ${CARGO_HOME:-$HOME/.cargo}/bin.

$git clone https://github.com/JanDub-code/AgentCage.git AgentCage && cd AgentCage && ./install.sh

The script installs to ~/.local/bin; Cargo installs to ${CARGO_HOME:-$HOME/.cargo}/bin. If your shell cannot find ac, add the install directories to PATH for the current shell:

$export PATH="$HOME/.local/bin:${CARGO_HOME:-$HOME/.cargo}/bin:$PATH" && hash -r && command -v ac && ac --help

Quick start

  1. Go to the project you want the agent to edit. Replace /path/to/project below with that directory; do not choose your home directory.
  2. Run ac once to create .agentcage/ and build agentcage/agent-tools:local. The first build downloads the tools and needs network access.
  3. Run your chosen agent. Normal runs reuse that agent's saved login files and persist selected auth changes when the session ends.
bash — your project
$cd /path/to/project && ac && ac codex

For a run without saved auth, use this after initialization:

$ac codex --no-login

To see the agent's own help, run ac codex -- --help. ac codex --help shows AgentCage help. Agent options follow --; --no-login and --env NAME are mutually exclusive.

If initialization or startup fails, read the Podman error and the troubleshooting steps. If the image is missing or outdated, run ac again in your project. Copy unavailable? Select the command text and press Ctrl+C (Cmd+C on macOS).

Pinned OpenCode 1.18.34 syncs account credentials as account.json and provider credentials as auth.json. Default login sync does not copy its SQLite database, chats, logs, or history to the host store. See OpenCode compatibility and validation limits.

What remains accessible and persistent

  • The agent can read, edit, and delete files in the mounted project. Keep backups or use a throwaway clone.
  • Host networking lets the agent contact the internet and services on the host. Tokens available to the agent can be sent over that network.
  • The default container home is disposable. Allowlisted login files persist in the host login store unless --no-login is used.
  • --env NAME reuses a full project-local container home, including any credentials, settings, and caches it contains.
  • Container removal preserves project edits, the built image, and saved state. Rootless containers share the host kernel and do not provide VM isolation.
